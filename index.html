☁️ Scheduled Cloud Crawler & Email Packages

TalentScout runs autonomously on GitHub Actions three times a day without committing any private data to this public repository. Each scheduled run restores deduplication state from runner cache, crawls fresh listings per profile, bundles only newly discovered roles into a portable .zip package, and delivers it over standard SMTP.

Schedule · UTC Cron

⏰ 3× Daily PST Windows

Triggered at 07:00, 13:00, and 21:00 PST (cron: '0 5,15,21 * * *') to match morning, midday, and evening role drops—plus on-demand workflow_dispatch runs with fast, ats-only, or full modes and a 20-minute soft budget.

Public-Repo Hygiene

🔐 Secrets-Only & Cache State

All SMTP credentials and recipient profiles live exclusively in GitHub Actions Secrets (never in Git). Deduplication state (job_tracker.db) persists in private runner cache with PRAGMA wal_checkpoint(TRUNCATE), and CI logs automatically mask email addresses.

Delta Packaging

📦 Portable ZIP + Local Import

SQLite profile_deliveries ensures each email contains strictly new roles. Each digest attaches a .zip (jobs_delta.json, jobs_summary.csv, jobs_digest.md, telemetry) ready for 1-command local import via scripts/import_package.py and local LLM tailoring.

Scalable Transport

👥 Multi-Profile via Stdlib SMTP

Works immediately for a single user via RECIPIENT_EMAIL, or scales to multiple profile users via TALENTSCOUT_PROFILES_JSON. Uses Python's stdlib smtplib (STARTTLS/SSL)—zero third-party email SDKs required.

🔀 Implementing on Non-GitHub Repository Managers

Every step—ci_bootstrap.py, ingest_dreamwork.py, auto_scour.py, and package_and_email.py—is platform-agnostic Python configured by environment variables. Swap GitHub Actions for any CI host or local scheduler by mapping these four pillars:

Platform / Host Scheduler Secrets Store SQLite State Persistence Key Implementation Note
GitHub Actions (default) on.schedule (0 5,15,21 * * * on main) Actions Repository Secrets actions/cache (7-day TTL refreshed 3×/day) Auto-pauses after 60 days without repo commits; keep packages out of public artifacts.
GitLab CI/CD Pipeline Schedules (native TZ support) CI/CD Variables (Masked + Protected) cache: or Generic Package Registry Use mcr.microsoft.com/playwright/python image and set resource_group: to prevent overlaps.
Bitbucket Pipelines Pipelines Schedules UI Secured Repository Variables Custom cache or S3/R2/B2 sync Use size: 2x for Chromium, or --mode ats-only on 1x runners.
Gitea / Forgejo Actions .forgejo/workflows/ (near 1:1 YAML) Actions Secrets Self-hosted runner volume mount Bind-mounting a host directory removes cache eviction limits entirely.
Self-Hosted (cron / Task Scheduler) Local TZ crontab (0 7,13,21 * * *) Restricted .env (chmod 600) Native on-disk job_tracker.db Residential IP avoids most cloud datacenter bot blocks; use flock to serialize runs.
Universal Checklist for Any Host: (1) Run PRAGMA wal_checkpoint(TRUNCATE) before caching/uploading job_tracker.db so WAL writes aren't lost; (2) enforce single-run concurrency; (3) never publish personalized digest ZIPs to public build artifacts; and (4) pair cloud datacenter runners with --mode fast or --mode ats-only plus --time-budget 20.
